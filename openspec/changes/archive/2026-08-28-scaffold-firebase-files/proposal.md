## Why

A newly scaffolded Blazing CMS project cannot deploy or run emulators until the
user manually runs `firebase init hosting` to create `firebase.json` and
`.firebaserc`; without them `blaze deploy` fails with a "firebase.json not
found" error. Scaffolding the Firebase deployment and Firestore files up front
removes that manual step and gives every generated project a valid, documented
starting point.

## What Changes

- The `create-app` scaffold writes four new files into every generated project:
  - `firebase.json` — Firebase Hosting + Firestore configuration (targets the
    admin SPA build output, wires up `firestore.rules`/`firestore.indexes.json`,
    and configures the emulator suite used by `blaze dev --emulator`)
  - `.firebaserc` — project alias mapping `default` to the placeholder project
    id that matches `.env` (`VITE_FIREBASE_PROJECT_ID`)
  - `firestore.rules` — a valid starter ruleset (RBAC helper skeleton + deny-all
    default), documented as regenerated by `blaze generate`
  - `firestore.indexes.json` — starter index file (`{ "indexes": [] }`),
    regenerated by `blaze generate`
- Scaffolded file templates ship from a new `packages/create-app/templates/`
  directory and are resolved at runtime, replacing the current
  `new URL("../AGENTS.md", import.meta.url)` pattern.
- **Fix**: the published `@blazing-cms/create-app` tarball currently omits
  `AGENTS.md` (the `files` field only ships `dist` and `bin`), so the AGENTS.md
  write would fail at runtime for npm consumers. The `templates/` directory is
  added to `files` so all template files are actually published.
- `AGENTS.md` template is updated to document the new files and the fact that
  `blaze generate` regenerates rules and indexes.

## Capabilities

### New Capabilities

- `project-scaffolding`: defines the files and structure `create-app` writes
  into a new project, including Firebase deployment configuration that makes a
  generated project deployable via `blaze deploy` without manual `firebase init`.

## Impact

- `packages/create-app/src/index.ts` — add `createFile` calls for the four new
  files; read templates from `templates/`.
- `packages/create-app/templates/` (new) — `firebase.json`, `.firebaserc`,
  `firestore.rules`, `firestore.indexes.json`, `AGENTS.md`.
- `packages/create-app/package.json` — add `"templates"` to `files`.
- `packages/create-app/AGENTS.md` — project layout + next-steps documentation.
- `packages/create-app/src/__tests__/index.test.ts` — assert the four new files
  are written and reference the template content.
- Verification: regenerate a sample project and confirm `blaze dev`,
  `firebase emulators:start`, and `blaze deploy` prerequisites are met.
